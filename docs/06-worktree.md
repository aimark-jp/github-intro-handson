# 06　並列で作業する

worktree（フォルダごと枝を分ける）

**当日はここだけ画面を見るだけです。** 手を動かさなくて大丈夫です。
あとから自分で試せるように、手順はこのページに残してあります。

---

## やること

03 では、**1つのフォルダの中で枝を切り替えて**作業しました。
切り替えるたびにファイルの中身が入れ替わるので、**同時に2つの作業はできません。**

`worktree` を使うと、**枝ごとに別のフォルダを用意できます。**
机をもう1つ出すようなものです。元のフォルダはそのまま、隣に別の枝のフォルダが並びます。

**AI に長い作業をさせている間、自分は別の枝で普通に作業を続けられます。** これが効きます。

---

## 貼るプロンプト

まず、いまの状態を確かめます。

```
いま github-intro-handson のどのフォルダの、どのブランチにいるか教えてください。
```

そのうえで、**隣にもう1つフォルダを作ります。**
`<自分のユーザー名>` のところだけ、自分のものに書き換えてください。

```
いまの github-intro-handson で、次をやってください。

・リポジトリの隣（1つ上の階層）に「github-intro-handson-wt」というフォルダを作り、
  そこに「wt-<自分のユーザー名>」という新しいブランチを worktree として用意する
・いまいるフォルダのブランチは切り替えないこと
・作り終わったら、いまある worktree の一覧を見せてください
・終わったら止まってください
```

できたら、**新しいフォルダの中だけで**変更を1つ作ってみます。

```
さっき作った worktree のフォルダの中で、次をやってください。

・practice/members/<自分のユーザー名>.md に1行足す
・その変更を記録する（push はしなくていい）
・終わったら、元のフォルダに戻って、いまどのブランチにいるか教えてください
・終わったら止まってください
```

**元のフォルダのブランチは、最初のままのはずです。** そこが確認したいところです。

片付けます。

```
さっき作った worktree のフォルダを取り外してください。
ブランチ自体は消さないでください。
```

---

## AI が返すはずのもの

```bash
git worktree add ../github-intro-handson-wt -b wt-<ユーザー名>   # 隣に新しいフォルダ＋新しい枝
git worktree list                                               # いまある作業フォルダの一覧
git worktree remove ../github-intro-handson-wt                  # フォルダを取り外す
```

`git worktree list` はこんな形で返ってきます。

```
/Users/you/github-intro-handson       c471f02 [add-<ユーザー名>]
/Users/you/github-intro-handson-wt    c471f02 [wt-<ユーザー名>]
```

**フォルダは2つ、`.git` は1つです。** 履歴は共有されているので、
新しいフォルダでコミットしたものは、元のフォルダから `git log wt-<ユーザー名>` でそのまま見えます。
**間で push / pull する必要はありません。**

**`-b` は「新しい枝を作る」です。** すでにある枝を開きたいときは `-b` を付けずに枝の名前を渡します。

```bash
git worktree add ../github-intro-handson-wt add-<ユーザー名>     # すでにある枝を開く場合
```

**同じ枝を2つのフォルダで同時には開けません。** ぶつからないようにするための仕組みです。

`git worktree remove` で消えるのは**フォルダだけ**です。**枝は残ります。**
枝も消したいときは、あとから `git branch -d <枝名>` を別に頼んでください。

---

## こうなれば成功

- `git worktree list` に**2行**並んでいる（元のフォルダと、新しいフォルダ）
- 新しいフォルダで記録した変更が、**元のフォルダのブランチには出てこない**
- それでも元のフォルダから `git log wt-<ユーザー名>` で、そのコミットが見える
- `git worktree remove` のあと、`git worktree list` が**1行**に戻っている
- `git branch` には `wt-<ユーザー名>` が**まだ残っている**

**フォルダを分けても、履歴は1つ。** ここが持ち帰るところです。

---

## つまずいたら

| 症状 | どうするか |
|---|---|
| `is already checked out at ...` | その枝を別のフォルダで開いています。「その worktree の場所を教えてください」と頼んでください |
| `contains modified or untracked files, use --force` | 記録していない変更が残っています。「先に記録してから取り外してください」と頼んでください |
| フォルダを手で消してしまい、一覧に残っている | 「`git worktree prune` で掃除してください」と頼んでください |
| どのフォルダがどの枝か分からなくなった | 「`git worktree list` を見せてください」と頼んでください |
| AI が元のフォルダで作業してしまった | 「いまどのフォルダにいますか？」と聞いて、正しいフォルダを指定し直してください |
| `worktree` を作った場所が分からない | 「worktree の絶対パスを教えてください」と頼んでください |
| 片付けたのに枝が残っている | **それで正しいです。** 枝を消したいときだけ `git branch -d` を別に頼んでください |
