# 07　コマンド早見表

今日出てきた git コマンドのまとめ

---

## 使い方

**覚えなくて大丈夫です。** コマンドを打つのは AI なので、
この表は「いま何をされているのか」を確かめるための**手元のカンニングペーパー**です。

見返したいときに開いてください。

---

## 早見表

| やりたいこと | コマンド | ひとこと説明 |
|---|---|---|
| クラウドから手元に持ってくる | `git clone <URL>` | 最初の1回だけ。フォルダごと降りてくる |
| いま何が変わったか一覧で見る | `git status` | 変わったファイルの名前が並ぶ |
| 中身がどう変わったか見る | `git diff` | `+` が増えた行、`-` が消えた行 |
| 記録するものを選ぶ | `git add <ファイル>` | 「これを記録します」と選ぶ。まだ記録はされない |
| 選んだものを記録する | `git commit -m "..."` | 選んだものに名前をつけて残す |
| クラウドに上げる | `git push` | ここで初めて GitHub 側に反映される |
| 枝を作ってそこに移る | `git switch -c <ブランチ名>` | 枝の上で何をしても `main` は無傷 |
| ブランチを移動する | `git switch <ブランチ名>` | `main` に戻るときもこれ |
| クラウドの様子を見に行く | `git fetch` | **見に行くだけ。** 手元のファイルは変わらない |
| クラウドの変更を受け取る | `git pull` | 見に行って、手元にも反映する |
| これまでの記録を並べて見る | `git log --oneline` | 新しい順に1行ずつ。積み上がっているのが見える |
| 記録していない変更を取り消す | `git restore <ファイル>` | 編集前の状態に戻る |

---

## 流れで見ると

**02 でやった1周**は、表の上から順に並んでいます。

```bash
git status          # 何が変わった？
git diff            # どう変わった？
git add README.md   # これを記録します
git commit -m "..." # 名前をつけて記録
git push            # クラウドに上げる
```

**編集 → status → diff → add → commit → push。**
今日やったことは、ほとんどがこの繰り返しです。

枝を使うときは、いちばん最初に `git switch -c` が付くだけです。

---

## 少しだけ気をつけるもの

| コマンド | 気をつけること |
|---|---|
| `git restore` | **まだ記録していない**変更を元に戻します。commit 済みのものは消えません |
| `git push` | `rejected` と出たら、クラウド側が先に進んでいます。`git pull` してからもう一度 |

不安なときは、打つ前に AI にこう聞けます。

```
いまから打とうとしているコマンドが、何をするものか説明してください。
```

---

## 迷ったら、この3つ

| 聞きたいこと | AI への頼み方 |
|---|---|
| いまどうなってる？ | 「いまの状態を `git status` で見せてください」 |
| 何を変えた？ | 「いまの差分を、増えた行と減った行に分けて説明してください」 |
| これまで何をした？ | 「これまでの記録を新しい順に並べて見せてください」 |

**コマンドを打つのは AI、確かめるのは自分。** これだけ持ち帰れば十分です。
