# 08　用語集

今日出てきた言葉を、あとから引くためのページ

---

## 使い方

このページは**上から順に読むものではありません。**
「あの言葉、なんだったっけ」と思ったときに、必要なところだけ探してください。

言い回しは各ページと合わせてあります。ページ内で使っている言葉（**枝**、**記録する**、**上げる** など）が、
git の用語ではどれにあたるのかも書いてあります。

---

## 場所の話

### リポジトリ

ファイルと、これまでの記録が入っている**入れもの**のことです。
「プロジェクトのフォルダ + 履歴」だと思っておけば足ります。
今日は、自分で作った `github-practice` と、みんなで触る `github-intro-handson` の2つを使いました。

### ローカル（手元）

自分の PC の中にあるほう。**エディタに映っているのはこちら**です。
ここで編集しても、まだクラウド側には何も伝わっていません。

### リモート（クラウド）

GitHub 側にあるほう。ブラウザで見えるのはこちらです。
他の人と共有しているのはこの1か所で、**ここに集めることでチームの作業がつながります。**

### origin

**リモートに付けた呼び名**です。「いつもの GitHub のあそこ」くらいの意味だと思ってください。
`git push -u origin ブランチ名` の `origin` がこれです。名前なので他の名前も付けられますが、
ふつうは `origin` の1つだけです。

---

## 記録の話

### コミット

**変更をひとかたまりにして記録すること**、またはその記録そのものです。
ドキュメントで「記録する」と言っているのはこれです。
一度コミットしておけば、あとからその時点の状態をいつでも見に行けます。

### 差分

**変えた前と後の違い**のことです。緑（足した行）と赤（消した行）で表示されます。
コミットする前と、PR の **Files changed** タブで見られます。
「何を変えたか」を確認する場所は、いつもここです。

### 履歴

コミットが並んだもの。**これまでの記録の一覧**です。
消したつもりのものも履歴には残るので、**戻したいときはここから戻せます。**

---

## 枝の話

### ブランチ

ドキュメントで**枝**と呼んでいるものです。
`main` を触らずに作業するための、分かれ道だと思ってください。
枝の上で何をしても `main` は無傷なので、**大きく書き換えるときほど安心して試せます。**

### main

**そのリポジトリの本線**です。ふつうは「これが完成しているもの」として扱います。
だから、いきなり `main` を書き換えるのではなく、枝で作業してから入れます。

### マージ

**枝でやったことを、`main` に取り込むこと**です。
GitHub の画面で緑の **Merge pull request** を押すと、これが起きます。
取り込んだあとも、枝でのコミットは履歴に残ります。

### コンフリクト（衝突）

**同じファイルの同じあたりを、2人が別々に変えたとき**に起きます。
git がどちらを採用すべきか決められないので、人間に聞いてくる、という状態です。
今日は1人1ファイルなので起きない想定です。**起きても壊れてはいません。**

## やりとりの話

### clone

**リモートのリポジトリを、まるごと手元に持ってくること**です。
最初の1回だけやります。2回目からは `pull` を使います。

### push

**手元の記録を、クラウドへ上げること**です。
push するまでは、自分の PC の中にしかありません。
初めて上げる枝には `-u origin ブランチ名` を付けます。

### fetch

**クラウド側がどうなっているかを、見に行くだけ。**
手元のファイルは変わりません。「向こうが進んでいるか」を確認するための操作です。

### pull

**見に行って、手元にも反映すること**です。fetch とセットになっている、と思っておけば足ります。
**作業を始める前に `git pull`。** 今日いちばん習慣にしてほしいのはこれです。

---

## 相談の話

### PR（プルリクエスト）

**「この枝の内容を `main` に入れていいですか」という申請**です。
差分が並び、行ごとにコメントが書けます。
コードは AI が書いてもいいですが、**入れていいかを決めるのは人間です。**

### レビュー

PR の差分を見て、**コメントで相談すること**です。
指摘だけの場ではありません。「ここどういう意図ですか」と聞くのもレビューです。

---

## 並列の話

### worktree

**同じリポジトリの別々のブランチを、別々のフォルダで同時に開ける仕組み**です。
ふだんは1つのフォルダで枝を切り替えますが、切り替えると画面の中身も入れ替わります。
worktree を使うと切り替えずに済むので、**複数の作業を並べて進められます。**

---

## それでも分からないときは

**AI に聞くのがいちばん早いです。** 用語をそのまま渡して構いません。

```
git の「fetch」と「pull」の違いを、いま私がやったことに沿って説明してください。
```

このドキュメントの言葉で聞き返してもらってもいいですし、
「いま自分がどうなっているか」を聞くのも同じくらい有効です。

```
いまどのフォルダの、どのブランチにいますか？
```
