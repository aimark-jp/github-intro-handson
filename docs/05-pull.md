# 05　他人の変更を受け取る

fetch / pull

---

## やること

**04 で、全員が同じリポジトリにマージしました。**
つまり今、クラウド側の `main` には**他の人のファイルが増えています。**

でも、あなたの手元はまだ何も知りません。それを持ってきます。

---

## 知っておくこと

ここでやるのは、**別々の2つの操作**です。

| 操作 | 何をするか |
|---|---|
| **fetch** | クラウド側がどうなっているか、**見に行くだけ。** 手元のファイルは変わらない |
| **pull** | 見に行って、**手元にも反映する** |

普段は `git pull` だけ使えば足ります。
ただ、**別々だと知っておくと「勝手に上書きされた」が起きません。**

---

## 貼るプロンプト

```
github-intro-handson のフォルダで、次を順番にやってください。

・main ブランチに切り替える
・まず git fetch だけを実行して、git status の結果を見せる
・そのあと git pull を実行して、practice/members/ の中身を見せる
・fetch と pull で何が違ったのかを説明してください
```

---

## AI が返すはずのもの

```bash
git switch main
git fetch     # 見に行くだけ
git status    # 「1つ遅れている」と出る
git pull      # 受け取る
ls practice/members/
```

`git fetch` のあとの `git status` に、こんな行が出ます。

```
Your branch is behind 'origin/main' by 12 commits, and can be fast-forwarded.
```

**「手元がその数だけ遅れている」**という意味です。数は人数とはぴったり合いません
（画面からマージすると、記録が1人につき2つ増えるためです）。**ここではまだファイルは変わっていません。**

そのあと `git pull` すると、`practice/members/` に**参加者全員のファイルが一気に増えます。**

---

## 覚えて帰ってほしいこと

**作業を始める前に `git pull`。**

他の人と一緒に使うときは、これが習慣になります。
今日みたいに、知らないうちにクラウド側が進んでいるからです。

AI に任せるときも、最初にこう言っておけば済みます。

```
作業を始める前に、まず git pull してください。
```

---

## こうなれば成功

- `git fetch` のあと `git status` に `behind` と出た
- `git pull` のあと、`practice/members/` に**他の人のファイルが増えている**
- fetch は見に行くだけ、pull は反映する、という違いを AI が説明できている

中身も見てみてください。

```
practice/members/ に増えたファイルを、何人分あるか数えて、いくつか中身を見せてください。
```

---

## つまずいたら

| 症状 | どうするか |
|---|---|
| `git status` に `behind` が出ない | まだ誰もマージしていないか、`main` にいません。「いまどのブランチですか？」と聞いてください |
| `Already up to date` で何も増えない | 上と同じです。少し待ってからもう一度 `git pull` を頼んでください |
| `You have unstaged changes` | 記録していない変更があります。「先に記録してから pull してください」と頼んでください |
| `CONFLICT` と出た | 1人1ファイルなので起きない想定です。チャットで声をかけてください |
| 自分のファイルが見当たらない | まだ 04 のマージが済んでいないかもしれません。PR が **Merged** になっているか見てください |
